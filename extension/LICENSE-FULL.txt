5. WHAT BEETHOVEN FOR VS CODE DOES WITH YOUR CREDENTIALS

This section describes the software as shipped, so that you can hold Licensor to it.

(a) Claude. Beethoven for VS Code never reads, stores, copies or relays a Claude credential. You
sign in to Claude Code yourself, through Anthropic's own flow, on your laptop and, once, in a
terminal inside your own grid account; Claude Code keeps its own credential there, and Beethoven for
VS Code only starts Claude Code where that credential already is. Beethoven for VS Code reads only
Claude Code's own report of that sign-in: whether it is signed in; whether with a Claude
subscription, a token, a cloud provider or an API key behind it (never the key itself); and the
e-mail and plan it names, which it shows to you. Only a sign-in with your own Claude subscription and
no API key behind it counts: the grid worker and phone access run nothing on any other, and
Beethoven for VS Code tells you that Claude is signed in, but not with a Claude subscription.
Beethoven for VS Code never deletes a Claude sign-in and never signs one out: to sign out, you run
claude auth logout yourself in a terminal (on the grid, on a compute node). Removing Beethoven for
VS Code from your grid account (Beethoven: Reset, or beethoven uninstall --yes in a terminal there)
removes only what it installed there: its scripts, settings, logs, worker folders and its block in
~/.bashrc. Your Claude sign-ins, your other accounts, your session history and your work folder on
the grid stay, as do the copies of your tokens and license key until you delete them. Every Claude
account you use is your own: you may hold several, and choose in the settings which one Claude Code signs in with
in every integrated terminal of a Visual Studio Code window on your laptop, including the terminals
you open yourself (a remote window's terminals run on another computer and are left as they are);
Beethoven for VS Code never pools accounts, never uses another person's, and never copies or moves a
sign-in between them.

(b) GitHub and Hugging Face tokens. With your consent in each step, Beethoven for VS Code stores
your GitHub token (obtained through Visual Studio Code's own GitHub sign-in) and your Hugging Face
token in your operating system's credential store, and copies them into a file readable only by you
in your own grid account, so that your own tools there can use them. You can delete them at any time
in Beethoven for VS Code and revoke them at GitHub and Hugging Face.

(c) No API key and no paid usage. Beethoven for VS Code runs Claude Code only on your own Claude
subscription. It never asks for, stores or uses an Anthropic API key or any other paid usage, and it
keeps the variables that would make Claude Code use one out of every Claude Code session it starts,
on the grid and on your laptop. When your subscription's usage window is spent, the worker answers
that it is rate-limited, with the time the window resets, and you send the request again after that.
Beethoven for VS Code cannot see or change the billing settings of your Claude account: if extra
usage (usage credits) is turned on there, Claude Code may draw on it, so keep it off. An Anthropic
Console key that Beethoven for VS Code 4.0.0 stored on your laptop, or that an earlier version
stored in your grid account, is never used or sent: Beethoven for VS Code only checks whether it is
there, and the first time it reaches your grid account it marks the grid copy disabled, so that a
worker the earlier version started cannot use it. It does not delete the key for you: you can delete
it (Beethoven: Manage stored tokens or Beethoven: Reset on your laptop; beethoven accounts remove
--yes in a terminal on the grid) and revoke it in the Anthropic Console. A key that Ashley for VS
Code stored on your laptop is in Ashley's own storage, which Beethoven for VS Code cannot reach:
delete it in Ashley for VS Code, or revoke it in the Anthropic Console, which makes every copy
useless.

(d) Your license key and the institutional identity you signed in with (AccessID and e-mail) are
stored on your laptop, and the key is copied to your grid account, where the Beethoven for VS Code
worker refuses to run without it.

(e) None of (a) to (d) is sent to Licensor. Section 10 describes the only things that may be.
